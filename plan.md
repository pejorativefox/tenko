## 1. What is done

**Base system**
- 93 LFS chapter-8 specs build **offline** (`--network=none`) inside the
  self-hosted container, producing 94 RPMs (glibc also ships `glibc-locales`).
- The rootfs boots to multi-user and serial login three ways: direct kernel
  (`scripts/qemu_boot.sh`), UEFI GRUB disk without `-kernel`
  (`scripts/make_efi_disk.sh`), and a dracut initramfs on NVMe.  Zero
  `FAILED` units in all three.
- Kernel 7.2.6-5 (`linux-kernel` / `linux-modules` / `linux-kernel-debug`),
  initramfs generated by `%post`, module signing off,
  `CONFIG_DRM_PANIC_SCREEN="user"`.
- glibc 2.44-3 with the curated 11.1 MB `glibc-locales` plus opt-in
  `glibc-locales-extra`; systemd 261.3-3; merged `/usr` with `/usr/lib64`.
- The base meta's requires are generated from `lfs.lock` by
  `scripts/gen_base_requires.py` (+ `requires-extra`), with `--check`.
  `browneye-base` now requires `make-ca`, so every installed system and
  derived image gets the Mozilla CA trust store (pulling `p11-kit` and
  `libtasn1`) without adding an explicit dependency to each profile.

**Desktop**
- XFCE 4.20, X11 only, zero Wayland: the 17 core packages plus Xorg 21.1.24,
  dbus, libinput, fonts, VTE 0.84.1 and xfce4-terminal 1.2.0.
- Mesa 26.2.3-4 (llvmpipe + virgl); glamor runs on virgl under
  `virtio-vga-gl`, llvmpipe/XRender on plain 2D.
- LightDM 1.33.1 + lightdm-gtk-greeter 2.0.9 (PAM, unit/preset, XFCE session),
  AccountsService 26.27.3 (greeter user list), sudo 1.9.17p2 (PAM, `%wheel`).
- librsvg 2.63.2 with the gdk-pixbuf SVG loader (built offline with the
  `/opt` Rust 1.99.0, vendored crates, plus cargo-c 0.10.25) — SVG icons and
  wallpapers render.
- Firefox 159.0 (`firefox-bin`, `/opt`) with alsa-lib 1.2.16.1.
- `scripts/qemu_boot_login.sh` verifies the real first-boot flow: tty1
  password prompt → marker → LightDM greeter; the second boot skips the
  prompt.  `build/login-test.img` boots to the greeter.

**Storage, containers and installer tooling**
- cryptsetup 2.8.8, LVM2 2.03.42 (+ libdevmapper), mdadm 4.6, libaio 0.3.113.
- ISO media: libburn/libisofs/libisoburn 1.5.8.pl02 (xorriso), squashfs-tools
  4.7.5 and mtools 4.0.50 (user-approved exceptions).
- UEFI: dosfstools 4.2, efibootmgr 18, efivar 39 (with the glibc 2.43+ patch).
- podman-bin 6.1.4 (user-approved static bundle under `/opt/podman-6.1.4`,
  crun/conmon/netavark/passt included; `k8s-file` logging, native overlay).
  Verified rootless in an installed VM: `podman info` rootless + overlay,
  `userns` map `1 100000 65536`, scratch `podman build`/`run` works.
- Podman networking tools: libpcap 1.10.7, nmap 7.991 (`nmap`, `ncat`,
  `nping`) and passt 2026_10_02.cba3570 (`passt`, `pasta`).  ncat comes from
  BLFS; passt/pasta is not in LFS/BLFS and is a user-approved upstream
  exception at the same tag bundled by podman-bin.  Rebuild with
  `PHASE=net scripts/build_blfs_stack.sh`.
- Privoxy 4.2.0 stable (not in LFS/BLFS; user-approved upstream exception):
  non-caching filtering web proxy with a systemd unit, a `privoxy` sysusers
  entry and the upstream HTML documentation.  Built with the default pcre2 +
  zlib feature set (no optional TLS/Brotli/Zstandard).  Rebuild with
  `PHASE=proxy scripts/build_blfs_stack.sh`.
- proxychains-ng 4.17 (not in LFS/BLFS; user-approved upstream exception):
  LD_PRELOAD TCP redirector with `/etc/proxychains.conf`, `proxychains4` and
  `proxychains4-daemon`.  Rebuild with the same `PHASE=proxy` run.
- htop 3.5.3 (not in LFS/BLFS; user-approved upstream exception), replacing
  the 3.2.2 spec from 2023.  Built offline in a podman container from a
  rootfs installed out of the Browneye repo (`browneye-base` + gcc, make,
  ncurses-devel, rpm), with capabilities, delay accounting, sensors and
  hwloc disabled because the base system has no libcap/libnl/lm_sensors/hwloc
  development files.  The payload is unchanged: `htop`, desktop entry, man
  page, pixmap and scalable icon.
- tea 0.14.2 (not in LFS/BLFS; user-requested upstream exception): the
  official Gitea CLI release binary — a single static Go program shipped
  as `/usr/bin/tea`, no strip, `AutoReq/AutoProv` off, requires `make-ca`
  for the HTTPS trust store.  Rebuilt with `./bbuild build tea` and
  published with `scripts/publish_rpm.sh` (RPM is 9.0 MB, orig 29 MB).

**Installer (UEFI)**
- `scripts/build_iso_uefi.sh` builds a 1.0 GB UEFI ISO: zstd squashfs live
  root with dracut `dmsquash-live` + overlayfs, a pruned on-ISO repo (259
  RPMs / 665 MB), standalone GRUB EFI and a FAT16 El Torito image with a GPT
  ESP entry.
- `browneye-installer` 13.1-6 (Python 3 + ncurses): select a GPT disk, delete
  partitions, install into one contiguous free region, reuse an existing ESP
  (else create 512 MiB), ext4 root (min 8 GiB) + 2 GiB swap.  Installs
  `browneye-base` + `xfce-desktop` + kernel/modules/dracut/GRUB/efibootmgr/
  dosfstools/dnf/opencode-bin/herdr, basefs first, UUID fstab, UEFI GRUB with
  `--no-nvram` + efibootmgr and `EFI/BOOT/BOOTX64.EFI`, admin in `wheel`,
  root locked, first-boot marker written, JSONL log on the ESP.
- Verified end to end: blank 20 GB GPT disk → install `OK` (10 steps) →
  installed disk boots UEFI to the LightDM greeter with the created `admin`.
- Installed-system package access: `browneye-release` 13.1-2 ships
  `/etc/yum.repos.d/browneye-13.1.repo`; the installer copies the on-ISO repo
  to `/var/lib/browneye/repo` with a `file://` repo; `browneye-sysconfig`
  13.1-3 ships `/etc/subuid`/`subgid`; the admin gets 100000-165535.
  `dnf --disablerepo=browneye-13.1 install browneye-build` completes offline
  (63 packages, createrepo_c usable), and a rootfs builds in a home directory
  with `unshare -r dnf --installroot`.

**Tooling, packaging and publishing**
- Self-hosted toolchain: rpm 4.18.1-4 (with `python3-rpm`), dnf 4.24.0,
  createrepo_c 1.2.6, `browneye-build` meta.  Repo/rootfs/image assembly needs
  no host dnf or createrepo.
- Splits: firmware vendor packs, `python-tests`, Fedora-style LLVM
  (`llvm-libs` 132.9 MB instead of 1008), runtime/toolchain, systemd/vim/
  kernel, glibc locales, and 111 desktop sources → 183 subpackages.
- Profile metas: `browneye-base-runtime` (70 pkgs / 305 MB),
  `browneye-base-build`, `xfce-desktop-core` (174 / 700 MB), `-hardware`,
  `-full`; `browneye-workstation` (node, OpenSSH, git, opencode, herdr, sudo,
  podman); `browneye-live` (installer environment).
- Version parity: no shipped package is below the current LFS/BLFS trunk.
  `lfs.lock` regenerated from trunk (`581459fa`); `sync_lfs_spec.py
  --all-base` reports 80/80.
- `bbuild` cleanup: exit codes, ORDER-only `all`, NEVRA conflict refusal,
  atomic source staging, repo-aware read-only query, 56 tests; legacy
  duplicate scripts removed.
- Published: **552 RPMs** at <https://tomfool.8bit.ca/browneye/packages/13.1/>.
  A remote `dnf install` resolves `browneye-base xfce-desktop` (212 pkgs) and
  `browneye-build` (62 pkgs); `ncat` and `pasta` resolve from the same repo.
  htop 3.5.3-1 and podman-bin 6.1.4-2 were published with
  `scripts/publish_rpm.sh`; `podman-bin` no longer ships `/etc/subuid` and

## 2. What is left

### B. Self-hosting and on-box rebuild

- [ ] **B1. Chapters 5–7 as bootstrap RPMs.**  Downgraded 2026-11-02: the
      published tree has no first-generation (Fedora-host-built) RPMs left.
      An audit of 65 sampled packages (toolchain, texinfo/tcl/expect/dejagnu,
      man-pages/iana-etc, kernel, desktop/Xorg/BLFS stack) found every one
      built inside a container (`hex` buildhost, Oct 31 wave), so the
      ancestry concern is closed and B1 is now purely a disaster-recovery
      option: regenerate a *first* artifact (seed) from sources alone with
      no browneye RPM and no seed image present (~26 cross/toolchain specs
      + filelists + a driver).  Nothing else on this list depends on it.
- [ ] **S1. Ship the build tree for on-box ISO rebuilds.**  The installed
      system has every package needed (repo access, ISO tools, podman,
      `browneye-build`), but not `scripts/`, `package_specs/`, `lfs.lock` or
      the source tarballs.  Package them (or a git-clone workflow) so an
      install can rebuild the ISO without the original checkout.
- [ ] **S2. Container build images on an installed system.**  The
      container-based scripts (`verify_base_in_container.sh`,
      `build_blfs_stack.sh`) expect `localhost/browneye/base:*` images that
      only exist on the build host.  Provide a bootstrapping path (import a
      rootfs tarball, or build the image from the installed system) so the
      container workflow runs on Browneye itself.

### D. Packaging debt

- [ ] **D1. sqlite SONAME.**  The library has no SONAME, so `NEEDED
      libsqlite3.so` makes the unversioned name a runtime ABI and the runtime
      package must ship it.  Build with `-Wl,-soname,libsqlite3.so.0` and
      rebuild consumers.
- [ ] **D2. LLVM libdir.**  LLVM installs into `/usr/lib` while the distro
      uses `/usr/lib64`; `xorg-server` needs `-Wl,-rpath-link,/usr/lib` and
      image builds patch `/etc/ld.so.conf`.  Build with
      `LLVM_LIBDIR_SUFFIX=64` (or move `libLLVM`) and drop the workarounds.
- [ ] **D3. Sign the repository.**  Deferred by decision: the tree stays
      unsigned (`gpgcheck=0`, `repo_gpgcheck=0`).
- [ ] **D6. Optional `-gir` splits.**  The last unapplied size lever from the
      desktop split wave.
- [ ] **D7. 104 spec-only specs below the books.**  They only matter if they
      are ever built; update the chain first if so.  (`unzip` additionally
      references a consolidated patch that is 404 upstream — drop the spec or
      source the patch.)
- [ ] **D8. Minor gaps.**  `xfce4-terminal` omits its man page (no
      `docbook-xsl-nons`); `curl` is built `--without-libpsl`; `rsync` is
      built `--disable-idn`; `libepoxy` uses host GL headers during the build.

### E. Verification and hygiene

- [ ] **E2. Clean single-run rebuild.**  Re-run the whole base set in one
      `OUT` directory to confirm 93/93 without substituting a separately
      built package.

## 5. Reproduce the current state

```bash
cd ~/browneye

# one package / a batch
./bbuild build zlib
./bbuild build grep sed tar coreutils --jobs 6
python3 -m unittest discover -s tests -q           # bbuild tests

# full offline base rebuild in the container (the self-hosting check)
OUT=build/container-rebuild-$(date +%Y%m%d-%H%M%S) \
  ./scripts/verify_base_in_container.sh
./scripts/show_rebuild_failures.sh build/container-rebuild-YYYYMMDD-N

# repo + rootfs + image from that output
./scripts/bootstrap_selfhosted.sh build/container-rebuild-YYYYMMDD-N
IMAGE=localhost/browneye/base:r13.1-selfhost-YYYYMMDD \
  OUT=build/container-rebuild-selfhost \
  ./scripts/verify_base_in_container.sh

# non-base BLFS/XFCE/desktop stack (resumable)
KEEP=0 PHASE=core       ./scripts/build_blfs_stack.sh
KEEP=1 PHASE=rest       ./scripts/build_blfs_stack.sh
KEEP=1 PHASE=xfce-deps  ./scripts/build_blfs_stack.sh
KEEP=1 PHASE=xfce       ./scripts/build_blfs_stack.sh
KEEP=1 PHASE=desktop    ./scripts/build_blfs_stack.sh

# assemble and publish (the single repo)
cp ~/rpmbuild/RPMS/x86_64/*.rpm build/rpm-staging/   # + wave worktree RPMs
./scripts/assemble_repo.sh
RSYNC_OPTS=-c ./scripts/publish_repo.sh

# publish a single package without mirroring the whole repo
./scripts/publish_rpm.sh ~/rpmbuild/RPMS/x86_64/htop-3.5.3-1.x86_64.rpm
PRUNE=1 ./scripts/publish_rpm.sh podman-bin-6.1.4-2.x86_64.rpm  # drop superseded

# installer ISO (UEFI, live root + pruned repo)
./scripts/make_iso_repo.sh              # refresh build/iso-repo
./scripts/build_iso_uefi.sh             # full clean build (1.0 GB)
SKIP_LIVE=1 ./scripts/build_iso_uefi.sh # reuse build/live-root
# automated test variant: ISO_AUTO=1 ISO_ANSWER=/path/answer.json
./scripts/qemu_test_installer.sh        # OVMF boot + screenshot

# boots
ROOTFS=build/rootfs-selfhost ./scripts/qemu_boot.sh    # direct kernel
./scripts/make_efi_disk.sh + OVMF qemu line            # UEFI GRUB, no -kernel
./scripts/qemu_boot_graphical.sh                       # legacy one-shot X capture
./scripts/qemu_boot_login.sh                           # first boot + greeter capture
SSH_FWD=2222 ./scripts/qemu_run_desktop.sh             # interactive, test pwd browneye1
```

Notes: `--jobs` parallelises package builds (auto 8); each `rpmbuild` gets
`-j16` from the macros; downloads are 12-way.  `publish_repo.sh` prunes to the
newest RPM per package and rsyncs with `--delete` to
`tomfool8@192.200.112.194:public_html/browneye/packages/13.1/` (port 53211).
`publish_rpm.sh` is the single-package counterpart: it downloads only
`repodata/`, merges the new RPMs in with `mergerepo_c --method nvr`,
refuses to upload if the merged set would be smaller than the published one,
and regenerates `index.html` from the server's own file listing (so no local
repo tree is needed).  `PRUNE=1` additionally deletes RPM files the merged
metadata no longer references.
`bootstrap_selfhosted.sh` refuses to run if any status file says `fail`.
RPMs built in a per-wave worktree **must** be copied into `build/rpm-staging`
before `assemble_repo.sh` (or passed via `EXTRA_RPM_DIRS`), otherwise they are
silently dropped.

python3 scripts/audit_versions.py                  # RPM/spec vs the books
./scripts/sync_lfs_spec.py --all-base              # dry run; expect 0 changes
./scripts/gen_base_requires.py --check             # browneye-base requires

## 6. Critical gotchas

1. **`sudo` needs a password.** Use `unshare -r` for rpm root-dir tests, dnf
   installroot, and tarballing mode-000 files like `/etc/shadow`.
2. **dnf is dnf5 on the host** — `-v` is invalid; use
   `--setopt=debuglevel=10` or `rpm --root ... --test` under `unshare -r`.
3. **`~/.rpmmacros` is required** (`_libdir=/usr/lib64`, debuginfo off,
   check-rpaths off, `%strip`).  `bbuild` prepends `rpmsupport/` to `PATH`.
4. **Host contamination is the main failure mode.** Specs disable Fedora-only
   extras: `--without-selinux` (glibc, coreutils, findutils, sed, tar, gettext,
   dbus), `--without-openssl` (coreutils), `--with-included-libxml` (gettext),
   `-D openssl=disabled` (kmod), `--disable-xkb` (kbd), `--without-wayland
   --disable-selinux` (vim), SELinux lines removed from iproute2's config.mk,
   and glibc/gcc/grub override CFLAGS/LDFLAGS to avoid Fedora LTO/hardening.
   "nothing provides libfoo.so" in the rootfs usually means a host link.
5. **Devel prefixes for host builds** live in `build/deps/` (expat, openssl,
   sqlite for python/dbus; libmd for libbsd; jinja2/markupsafe for systemd;
   popt/file/libarchive/lua/libelf for the RPM toolchain).
6. **Static filelists need care when versions change.** Regenerate with
   `scripts/gen_filelist_tree.py`; do **not** repackage with
   `rpmbuild --short-circuit` (unsatisfiable `rpmlib(ShortCircuited)`).
7. **`.spec` globs are gone for the base set**: upstream file additions now
   fail the build (intended).
8. **Use `:z`, not `:Z`, for container mounts** of `package_specs`; `:Z`
   relabels the shared tree and breaks a running rebuild.
9. **Kernel headers come from the kernel source** (`linux-api-headers` runs
   `make headers` + copies `usr/include`; 1078 entries).
10. **`rpm` owns `/rpmbuild` in the container.** Mount sources read-only and
    copy RPMs out.
11. **Scriptlet-enabled installs need `browneye-basefs` first.**  Every
    scriptlet runs through `/bin/sh`, which only exists once basefs has
    created the merged `/usr` symlinks; dnf otherwise schedules basefs last
    and every `%pre`/`%post` fails with 127.  Install basefs in a separate
    transaction (the installer does the same).
12. **LLVM is in `/usr/lib`, not `/usr/lib64`** — see §2 D2.
13. **Kernel modules are xz-compressed**: kmod needs xz support; on 7.2 both
    `CONFIG_MODULE_COMPRESS_XZ` and `CONFIG_MODULE_COMPRESS_ALL` must be on.
14. **`CONFIG_MODPROBE_PATH="/usr/bin/modprobe"`**: kmod 34.2-2 installs that
    symlink.  Without it, `request_module()` autoload silently fails.
15. **`/usr/sbin` compatibility**: util-linux installs into `/usr/bin`, while
    `getty@.service` expects `/usr/sbin/agetty`; the spec creates the symlinks.
16. **`build/repo` is stale history**; never publish it.  `build/repo-all` is
    the tree that gets published.
17. **The on-ISO repo must be regenerated for every ISO build** (the script
    now does).  A cached `build/iso-repo` silently ships old RPMs — this is
    how `browneye-sysconfig-2` (no `/etc/subuid`) got into an earlier ISO.
18. **The El Torito EFI image must be FAT16.**  FAT32 on a 24 MiB image is
    below the 65525-cluster minimum and OVMF refuses to boot it.
19. **Never read `/run/initramfs/livedev` as text.**  On dracut-ng it is a
    symlink to the live block device; following it reads the whole ISO into
    memory (the installer once grew to 3.7 GB and was OOM-killed).  Resolve
    the link, and never `read()` non-regular files.
20. **OVMF `-kernel` does not attach the install CD.**  Automated installer
    tests must boot the ISO through GRUB; use the test ISO flags
    (`ISO_AUTO=1 ISO_ANSWER=...`) rather than direct-kernel boot.
21. **podman-bin is a static bundle in `/opt`**, not an RPM dependency chain.
    Its configs use `k8s-file` logging and native overlay; `/etc/subuid` and
    `/etc/subgid` must exist before users are created (browneye-sysconfig).
22. **The build container images are local to the build host.**  An installed
    system has podman and the packages, but not `localhost/browneye/base:*`
    (see S2).
23. **`mergerepo_c` must be run with `--omit-baseurl`, and old metadata
    cannot be trusted.**  Without the flag every package is stamped with
    `xml:base` pointing at the local staging directory, and dnf then tries
    `http://repo-old/<rpm>`.  Merging also *preserves* `xml:base` already
    present in the published metadata, so it has to be stripped and
    `repomd.xml` regenerated with `modifyrepo_c`; `scripts/publish_rpm.sh`
    does both and refuses to upload if any `xml:base` survives.  (Also: never
    use `grep -q` after `zstd -dc` under `pipefail` in that script — SIGPIPE
    makes the check silently pass.)

## 7. Technical debt and caveats

- The first-generation base was built against the Fedora 44 host; always
  confirm changes with a container rebuild before republishing.
- The repo is unsigned (`gpgcheck=0`) and pruned to one version per package
  name (D39).
- `browneye-base` requires are generated from `lfs.lock`; the split-package
  extras stay in `requires-extra`.
- `/etc/machine-id` ships empty (0444) and systemd generates one on first
  boot.  The journal is persistent (`/var/log/journal`, 512M cap); networking
  defaults to DHCP on `en*`/`eth*` via networkd/resolved.
- The installed system carries a copy of the on-ISO repo in
  `/var/lib/browneye/repo` (~665 MB); it is the offline package source.
- The ISO does not ship `scripts/`, `package_specs/`, sources or the container
  images (S1/S2).  Packages and podman are installable from the local repo.
- podman-bin is a single-maintainer static bundle (GPL helpers included):
  not rebuildable from Browneye sources and invisible to RPM CVE tracking.
- Console/tty logins do not get `pam_systemd` (no `/etc/pam.d/login`), so
  there is no `XDG_RUNTIME_DIR`; SSH and LightDM sessions are fine.
- The installer-created admin has subuid/subgid 100000-165535; other users
  created later get ranges from `login.defs` now that the files exist.
- The ISO is **UEFI-only and unsigned**: firmware with Secure Boot rejects
  `BOOTX64.EFI` (`Access Denied -- rejected probably by Secure Boot`).
  GNOME Boxes may default to Secure Boot; boot the VM with the non-secboot
  OVMF firmware (`/usr/share/edk2/ovmf/OVMF_CODE.fd`) or disable Secure Boot
  in the domain.  BIOS mode cannot work (no syslinux/isolinux).
  libvirt detail: keep `<os firmware="efi">` out of the domain and give an
  explicit `<loader>/<nvram>`; the `firmware` attribute makes libvirt
  autoselect `OVMF_CODE_4M.secboot.qcow2` (with `smm=on`) and ignore the
  explicit loader, which is exactly the failure seen in GNOME Boxes.
- The QEMU std-VGA `screendump` is blank with modesetting, so the graphical
  test captures the root window with `xwd` over a 9p share
  (`build/qemu-share/`).  `qemu_run_desktop.sh` has no `-virtfs`, so its 9p
  unit logs a cosmetic `no channels available for device host0`.
- The greeter test image is 6 GB (`IMGSIZE`).  It runs the real first-boot
  flow; the automated run leaves root at `browneye1` on tty1 (test only).
- Image builds run as fake root, so lightdm's `%post` cannot chown its state
  directories and the script relaxes their modes for the test image.
- `polkit` is built with `authfw=shadow`; `libnotify` with `-Dtests=false`.
- `libwnck` 43.1's BLFS checksum is stale; the actual tarball md5 is used.
- `xkeyboard-config` 2.48 emits non-fatal "Could not resolve keysym" warnings
  with `xkbcomp` 1.5.0.
- `systemd` is configured with `importd=disabled`, `remote=disabled` and
  `imds=disabled` so the base does not depend on `curl`, so
  `systemd-journal-remote` is not shipped.
- `linux-firmware` is a curated snapshot (D10), not a book package; URLs and
  sha256 are in the spec changelog.
- `vte` bundles simdutf/fmt/fast_float as subproject wraps for offline builds;
  they are static internals, not shipped packages.
- Deviations: glibc `upstream_fixes-3` (D7); `rsync --disable-idn`;
  `lua` 5.4.8 uses the renamed 5.4.6 shared-library patch (book URL 404);
  `gdk-pixbuf` keeps PNG/JPEG, no glycin; `lightdm` skips the yelp/gtk-doc
  docs and ships no Upstart/AppArmor/AccountsService-symlink artifacts;
  `librsvg` disables Vala bindings (in-tree vala is below the book);
  `podman-bin` is a static bundle under `/opt` (D46); `dosfstools` ships the
  book's compat symlinks; `efivar` carries the book's upstream-fixes patch;
  `tea` 0.14.2 ships the official static binary (D51).
- Backups: `~/backup/browneye/sources/` (2.8 GB, SHA256SUMS) and
  `~/backup/browneye-current` for the older staging tree.
