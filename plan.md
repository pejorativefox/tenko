## 1. What is done

**Base system**
- 93 LFS chapter-8 specs build **offline** (`--network=none`) inside the
  self-hosted container, producing 94 RPMs (glibc also ships `glibc-locales`).
- The rootfs boots to multi-user and serial login three ways: direct kernel
  (`scripts/qemu_boot.sh`), UEFI GRUB disk without `-kernel`
  (`scripts/make_efi_disk.sh`), and a dracut initramfs on NVMe.  Zero
  `FAILED` units in all three.
- Kernel 7.2.6-4 (`linux-kernel` / `linux-modules` / `linux-kernel-debug`),
  initramfs generated by `%post`, module signing off.
- glibc 2.44-3 with the curated 11.1 MB `glibc-locales` plus opt-in
  `glibc-locales-extra`; systemd 261.3-3; merged `/usr` with `/usr/lib64`.

**Desktop**
- XFCE 4.20, X11 only, zero Wayland: the 17 core packages plus Xorg 21.1.24,
  dbus, libinput, fonts, VTE 0.84.1 and xfce4-terminal 1.2.0.
- Mesa 26.2.3-4 (llvmpipe + virgl); glamor runs on virgl under
  `virtio-vga-gl`, llvmpipe/XRender on plain 2D.
- `build/login-test.img` boots to the **LightDM greeter** with the real
  first-boot password prompt (`scripts/qemu_boot_login.sh`); a second boot
  skips the prompt.  The old one-shot-X `xfce-test.img` flow is retired.
- Firefox 159.0 (`firefox-bin`, `/opt`) with alsa-lib 1.2.16.1.
- LightDM 1.33.1 + lightdm-gtk-greeter 2.0.9 (PAM, systemd unit
  `lightdm.service` aliased to `display-manager.service`, systemd preset,
  XFCE session), pulled in by the `xfce-desktop` meta (4.20-6), which also
  sets `graphical.target` as the default in `%post`.

**Developer workstation**
- node 26.13.0 and rust 1.99.0 as official binaries under `/opt`.
- Linux-PAM 1.7.3, PAM-enabled systemd 261.3-3, OpenSSH 10.5p1 (password
  auth), `browneye-firstboot` prompting for the root password on first boot.
- make-ca 1.16.1 (121 roots), git 2.55.0, which 2.25, opencode-bin 2.2.5,
  herdr 0.9.5, `browneye-workstation` meta.  Verified over SSH.

**Size and packaging**
- Splits: firmware vendor packs, `python-tests`, Fedora-style LLVM
  (`llvm-libs` 132.9 MB instead of 1008), runtime/toolchain, systemd/vim/
  kernel, glibc locales, and 111 desktop sources → 183 subpackages

  `-full`.
- Measured: `browneye-base` 105 pkgs / 707 MB; `browneye-base` +

**Tooling and parity**
- Self-hosted toolchain: rpm 4.18.1-4 (with a real `python3-rpm`), dnf 4.24.0,
  createrepo_c 1.2.6, `browneye-build` meta.  Repo/rootfs/image assembly needs

- Version parity: no shipped package is below the current LFS/BLFS trunk.

## 2. What is left

### A. Blocked on a decision from the user

- [ ] **A1. Installer ISO tooling.** `squashfs-tools`, `mtools`, `syslinux`
      and `busybox` are not in LFS/BLFS; `efivar` and `xorriso` are below the
      book.  Decide: build them as approved exceptions, use another live-media
      approach, or defer the ISO.
- [ ] **A2. Storage stack.** `cryptsetup`, `lvm2` and `mdadm` were deferred.
      dracut already supports LUKS/LVM/RAID roots, but the userspace tools are
      not packaged, so those roots cannot be set up after install.
- [ ] **A3. SVG icons.** `gdk-pixbuf` has glycin disabled and `librsvg` is
      absent, so SVG icons/wallpapers do not render.  `librsvg` needs a Rust
      toolchain (we only ship the `/opt` binary distribution).  Decide whether
      to build Rust from source or accept PNG-only icons.
- [x] **A4. `xf86-video-amdgpu` 23.0.0.**  Merged from `amdgpu-driver`
      (`a26999b`, cherry-picked as `298724b`), rebuilt with the static
      filelist and published.  Deliberately **not** in any meta: not every
      system needs it, so AMD users install it explicitly
      (`dnf install xf86-video-amdgpu`).
- [ ] **A5. Retire `system-minimal`?** It is legacy (its five broken requires
      are fixed so it installs again), but `browneye-base` /
      `browneye-base-runtime` supersede it.  Delete it or leave it as-is.

### B. Self-hosting

- [ ] **B1. D2 — chapters 5–7 as bootstrap RPMs.**  The container still relies
      on the chapter-8 toolchain; there are no cross-toolchain/temp-tools
      packages.  This is the largest remaining self-hosting gap.

### C. Installer and desktop

- [ ] **C1. Installer ISO.**  Live and target package sets (live runtime is
      `browneye-base-runtime`, ~305 MB) plus the media tooling from A1.
- [x] **C2. Display manager.**  LightDM 1.33.1 and lightdm-gtk-greeter
      2.0.9 are packaged (systemd unit + preset, PAM service, GTK greeter,
      XFCE session) and pulled in by `xfce-desktop` 4.20-6, which also sets
      `graphical.target` in `%post` so the greeter starts on boot.  Build
      chain added: libgcrypt 1.12.4,
      intltool 0.51.0 and the BLFS perl modules it needs (XML-Parser 2.59,
      File-ShareDir 1.118, File-ShareDir-Install 0.14, Class-Inspector 1.36).
      Verified in the container (`lightdm --version`, greeter runs and reads
      its config, `systemd-analyze verify` clean) and by a `dnf --installroot`
      install (user/group created, preset applied).  Needs a graphical boot
      test; `xfce-desktop` now sets `graphical.target`, so a normal install
      boots to the greeter (C3 still needs the test image reworked).
- [x] **C3. Test-image hygiene.**  `scripts/qemu_boot_login.sh` builds the
      desktop rootfs with scriptlets **enabled** (installing
      `browneye-basefs` first so `/bin/sh` exists), leaves root locked and
      boots the real first-boot flow: `browneye-firstboot` prompts on tty1,
      the password is typed through the QEMU monitor, and LightDM starts on
      `graphical.target`.  Verified with screenshots of the prompt and the
      greeter plus a second boot that skips the prompt.  No `getty@tty1`
      mask and no test password baked into the image.

### D. Packaging debt

- [ ] **D1. sqlite SONAME.**  The library has no SONAME, so `NEEDED
      libsqlite3.so` makes the unversioned name a runtime ABI and the runtime
      package must ship it.  Build with `-Wl,-soname,libsqlite3.so.0` and
      rebuild consumers.
- [ ] **D2. LLVM libdir.**  LLVM installs into `/usr/lib` while the distro
      uses `/usr/lib64`; `xorg-server` needs `-Wl,-rpath-link,/usr/lib` and
      image builds patch `/etc/ld.so.conf`.  Build with
      `LLVM_LIBDIR_SUFFIX=64` (or move `libLLVM`) and drop the workarounds.
- [ ] **D3. Sign the repository.**  It is unsigned (`gpgcheck=0`); a signing
      key and `repo_gpgcheck` path are needed.
- [x] **D4. Auto-generate `browneye-base` requires.**  The ~100
      `Requires:` lines are now generated: `scripts/gen_base_requires.py`
      expands `lfs.lock` `base_packages` through its alias map, splits
      `dbus`/`vim`, and appends the explicit extras in
      `package_specs/browneye-base/requires-extra`.  `--check` reports a
      stale block.  The generated set is identical to the old hand-written
      one.
- [x] **D5. Scriptlet testing.**  First full pass done with C3: a
      `dnf --installroot` desktop install with scriptlets enabled (after
      installing `browneye-basefs` first) completed with **zero** scriptlet
      failures, and the resulting image boots through the first-boot policy
      to LightDM.  The only noise is lightdm's `%post` `install -o lightdm`
      failing under fake root (userns cannot chown to uid 65); it works on a
      real root install.  Remaining: repeat for the installer/ISO path.
- [ ] **D6. Optional `-gir` splits.**  The last unapplied size lever from the
      desktop split wave.
- [ ] **D7. 104 spec-only specs below the books.**  They only matter if they
      are ever built; update the chain first if so.  (`unzip` and
      `autoconf213` additionally reference consolidated patches that are 404
      upstream — drop those specs or source the patches.)  `xml-parser` and
      `libgcrypt` were pulled up to the books for C2.
- [ ] **D8. Minor gaps.**  `xfce4-terminal` omits its man page (no
      `docbook-xsl-nons`); `curl` is built `--without-libpsl`; `rsync` is
      built `--disable-idn`; `libepoxy` uses host GL headers during the build.

### E. Verification and hygiene

- [x] **E1. First-boot account policy (old E5).**  Verified end to end with
      `scripts/qemu_boot_login.sh`: the locked root account triggers the tty1
      prompt, the password is accepted, the marker is written, and the
      greeter starts afterwards.  A second boot finds the marker and skips
      the prompt.  `browneye-firstboot` 13.1-2 orders the prompt
      `Before=display-manager.service` so LightDM cannot take tty1 while
      `passwd` is waiting.
- [ ] **E2. Clean single-run rebuild.**  The C1/C3 container run substituted a
      separately built `browneye-sysconfig`; re-run the whole base set in one
      `OUT` directory to confirm 93/93 without substitution.
- [x] **E3. Kernel cosmetic warning.**  `CONFIG_DRM_PANIC_SCREEN` is now
      `"user"` (the QR formatter needs `CONFIG_DRM_PANIC_SCREEN_QR_CODE`,
      which needs Rust and is off).  Linux 7.2.6-5 carries the fix; the
      config in `linux-kernel-debug` confirms the value.

## 6. Critical gotchas

1. **`sudo` needs a password.** Use `unshare -r` for rpm root-dir tests, dnf
   installroot, and tarballing mode-000 files like `/etc/shadow`.
2. **dnf is dnf5 on the host** — `-v` is invalid; use
   `--setopt=debuglevel=10` or `rpm --root ... --test` under `unshare -r`.
3. **`~/.rpmmacros` is required** (`_libdir=/usr/lib64`, debuginfo off,
   check-rpaths off, `%strip`).  `bbuild` prepends `rpmsupport/` to `PATH`.
4. **Host contamination is the main failure mode.** Specs disable Fedora-only
   extras: `--without-selinux` (glibc, coreutils, findutils, sed, tar, gettext,
   dbus), `--without-openssl` (coreutils), `--with-included-libxml` (gettext),
   `-D openssl=disabled` (kmod), `--disable-xkb` (kbd), `--without-wayland
   --disable-selinux` (vim), SELinux lines removed from iproute2's config.mk,
   and glibc/gcc/grub override CFLAGS/LDFLAGS to avoid Fedora LTO/hardening.
   "nothing provides libfoo.so" in the rootfs usually means a host link.
5. **Devel prefixes for host builds** live in `build/deps/` (expat, openssl,
   sqlite for python/dbus; libmd for libbsd; jinja2/markupsafe for systemd;
   popt/file/libarchive/lua/libelf for the RPM toolchain).
6. **Static filelists need care when versions change.** Regenerate with
   `scripts/gen_filelist_tree.py`; do **not** repackage with
   `rpmbuild --short-circuit` (unsatisfiable `rpmlib(ShortCircuited)`).
7. **`.spec` globs are gone for the base set**: upstream file additions now
   fail the build (intended).  `unzip`/`autoconf213` are spec-only leftovers.
8. **Use `:z`, not `:Z`, for container mounts** of `package_specs`; `:Z`
   relabels the shared tree and breaks a running rebuild.
9. **Kernel headers come from the kernel source** (`linux-api-headers` runs
   `make headers` + copies `usr/include`; 1078 entries).
10. **`rpm` owns `/rpmbuild` in the container.** Mount sources read-only and
    copy RPMs out.
11. **Scriptlet-enabled installs need `browneye-basefs` first.**  Every
    scriptlet runs through `/bin/sh`, which only exists once basefs has
    created the merged `/usr` symlinks; dnf otherwise schedules basefs last
    and every `%pre`/`%post` fails with 127.  Install basefs in a separate
    transaction (the installer must do the same) before the real package set.
12. **LLVM is in `/usr/lib`, not `/usr/lib64`** — see §2 D2.
12. **Kernel modules are xz-compressed**: kmod needs xz support; on 7.2 both
    `CONFIG_MODULE_COMPRESS_XZ` and `CONFIG_MODULE_COMPRESS_ALL` must be on.
13. **`CONFIG_MODPROBE_PATH="/usr/bin/modprobe"`**: kmod 34.2-2 installs that
    symlink.  Without it, `request_module()` autoload silently fails.
14. **`/usr/sbin` compatibility**: util-linux installs into `/usr/bin`, while
    `getty@.service` expects `/usr/sbin/agetty`; the spec creates the symlinks.
    Missing them makes getty disallocate the VT and kicks X off tty1 (looks
    like a session crash).
15. **`build/repo` is stale history** (old host-built versions); never publish
    it.  `build/repo-all` is the tree that gets published.

## 7. Technical debt and caveats

- The first-generation base was built against the Fedora 44 host; always
  confirm changes with a container rebuild before republishing.
- The repo is unsigned and pruned to one version per package name.
- `browneye-base` requires are hand-maintained (D4 above).
- `/etc/machine-id` ships empty (0444) and systemd generates one on first boot.
  The journal is persistent (`/var/log/journal`, 512M cap); networking defaults
  to DHCP on `en*`/`eth*` via networkd/resolved.
- No display manager, no SVG loader, no SELinux, no module signing — see the
  decision table and A3/C2.
- The QEMU std-VGA `screendump` is blank with modesetting, so the graphical
  test captures the root window with `xwd` over a 9p share
  (`build/qemu-share/`).  `qemu_run_desktop.sh` has no `-virtfs`, so its 9p
  unit logs a cosmetic `no channels available for device host0`.
- The greeter test image is 6 GB (`IMGSIZE`).  It runs the real first-boot
  flow; the automated run leaves root at `browneye1` on tty1 (test only).
  Image builds run as fake root, so lightdm's `%post` cannot chown its
  state directories and the script relaxes their modes for the test image.
- `polkit` is built with `authfw=shadow`; `libnotify` with `-Dtests=false`.
- `libwnck` 43.1's BLFS checksum is stale; the actual tarball md5 is used.
- `xkeyboard-config` 2.48 emits non-fatal "Could not resolve keysym" warnings
  with `xkbcomp` 1.5.0.
- `system-minimal` is legacy and unused; see A5.
- `systemd` is configured with `importd=disabled`, `remote=disabled` and
  `imds=disabled` so the base does not depend on `curl`, so
  `systemd-journal-remote` is not shipped.
- `linux-firmware` is a curated snapshot (D10), not a book package; URLs and
  sha256 are in the spec changelog.
- `vte` bundles simdutf/fmt/fast_float as subproject wraps for offline builds;
  they are static internals, not shipped packages.
- Deviations: glibc `upstream_fixes-3` (D7); `rsync --disable-idn`;
  `lua` 5.4.8 uses the renamed 5.4.6 shared-library patch (book URL 404,
  tracked in `package_specs/lua/files/`); `gdk-pixbuf` keeps PNG/JPEG, no
  glycin; `lightdm` skips the yelp help and gtk-doc API docs (no
  yelp-tools/gtk-doc) and ships no Upstart job, AppArmor profiles or
  dangling AccountsService interface symlink.
- Backups: `~/backup/browneye/sources/` (2.8 GB, SHA256SUMS) and
  `~/backup/browneye-current` for the older staging tree.
